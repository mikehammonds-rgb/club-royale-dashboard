# Club Royale Dashboard Project Map

## Runtime flow

```text
Request /
  -> app/page.tsx redirects to /index.html
  -> public/index.html loads public/styles.css
  -> public/index.html loads public/data/*.js in dependency order
  -> public/index.html loads public/app.js
  -> app.js renders Overview, Offers, Finder, and Trips
  -> app.js reads/writes member-scoped state through /api/state
  -> /api/state uses Cloudflare D1 when DB exists, otherwise seed/local fallback
```

The files under `public/` are build-time copies. The editable counterparts are at the repository root and under `data/`.

## Application shell and presentation

| File | Responsibility | Edit policy |
|---|---|---|
| `app/page.tsx` | Redirects the Next root route to the static dashboard. | Change only if routing changes intentionally. |
| `app/layout.tsx` | Next application layout/metadata shell. | Canonical framework source. |
| `app/globals.css` | Framework-level global styles. | Separate from the static dashboard stylesheet. |
| `index.html` | Canonical dashboard markup: header/member switcher, four views, dialogs, bottom navigation, data-script order, PWA metadata. | Edit this file, not `public/index.html`. |
| `app.js` | Canonical client logic: data expansion, member activation, rendering, Finder filters/scoring, local/cloud state hydration, dialogs, navigation. | Edit this file, not `public/app.js`. |
| `styles.css` | Canonical responsive/mobile-first styling. | Edit this file, not `public/styles.css`. |
| `public/index.html`, `public/app.js`, `public/styles.css` | Files served by the built site. | Generated by `scripts/sync-static.mjs`; never hand-edit. |
| `public/manifest.webmanifest`, `public/icons/*`, `public/og.png` | PWA and social assets. | Preserve paths referenced by `index.html`. |

## Product modules

| Module | Markup | Logic/data |
|---|---|---|
| Member selection/profile | `index.html` header and profile dialog | `activateMemberData`, `switchActiveMember`, `renderMemberIdentity` in `app.js`; `data/member-profiles.js` |
| Overview/action center | `#overview` | `renderMetrics`, `renderOfferPreview`, `renderChangeCenter`, `renderOverviewPlanning`; active offers, bookings, portal snapshot |
| Offer library/ledger | `#offers` | `allOffers`, `allOfferSlots`, `offerCard`, `renderOfferLibrary`; member offers and saved statuses |
| Offer Compass/Finder | `#finder` | sailing expansion, filters, ranking, grouping, comparisons, saved searches, Christmas preset in `app.js`; member sailing groups |
| Trips/calendar | `#trips` and trip dialog | `renderTrips`, calendar and booking persistence in `app.js`; `data/booked-cruises.js` plus D1/local changes |
| Update instructions | `#sync-dialog` | Status populated from active member profile; opens from `#open-sync` and `#open-sync-secondary` |
| Cloud state | none | `app/api/state/route.ts`, `db/schema.ts`, D1 binding `DB` |

## Canonical data files

| File | Current role |
|---|---|
| `data/club-royale-data.js` | Mike's active offer map (`MIKE_OFFERS`). |
| `data/live-sailing-groups.js` | Mike's active eligible itinerary groups (`MIKE_ROYAL_SAILING_GROUPS`). |
| `data/tully-data.js` | Tully's offer map and eligible itinerary groups. One FreePlay-only offer can be present with `comp: false` and is excluded from Finder results. |
| `data/member-profiles.js` | Member registry, active data references, profile display fields, snapshot date, returned-offer markers, and portal reconciliation summary. |
| `data/booked-cruises.js` | Seeded confirmed cruises for Mike. Bookings remain even when their originating offer is no longer active. |
| `data/mike-26pas603.js` | Preserved Aug. 29 sailing snapshot for booked offer `26PAS603`; loaded for historical availability but not part of `MIKE_ROYAL_SAILING_GROUPS` or the active Finder. Do not silently merge it into active results. |

Each canonical data file is copied to `public/data/` by `scripts/sync-static.mjs`.

## Persistence and database

| File | Responsibility |
|---|---|
| `app/api/state/route.ts` | GET hydration and POST actions (`save_searches`, `save_status`, `save_booking`); member allowlist; seed profiles/bookings; idempotent D1 initialization and historical snapshot migrations. |
| `db/schema.ts` | Current D1 tables and indexes. Member-scoped tables are the active model; legacy single-member tables remain for migration compatibility. |
| `drizzle/0000_club_royale_workspace.sql` | Initial persistence schema. |
| `drizzle/0001_multi_member.sql` | Multi-member migration. |

Browser persistence keys are member-suffixed versions of `club-royale-saved-searches-v1`, `club-royale-offer-statuses-v1`, and `club-royale-bookings-v1`. Mike can fall back to legacy unsuffixed keys for migration compatibility.

## Build, maintenance, and hosting

| File | Responsibility |
|---|---|
| `package.json` | `pnpm sync-static`, `pnpm dev`, `pnpm build`, and `pnpm start`; Node `>=22.13.0`. |
| `scripts/sync-static.mjs` | Copies canonical UI/data files into `public/`. |
| `next.config.ts`, `vite.config.ts`, `tsconfig.json` | vinext/Vite/TypeScript configuration. |
| `.openai/hosting.json` | Existing OpenAI Site project ID and D1 binding (`DB`). Preserve the project ID. |
| `maintenance/build_*.mjs`, `maintenance/build_data.py`, `maintenance/refresh-2026-08-26.mjs` | One-off/historical import and transformation utilities. Inspect inputs and output targets before reuse; they are not a universal current refresh command. |
| `maintenance/docs/*` | Historical research and procedures, partly superseded. Not the current architecture source of truth. |
| `NEXT_SESSION.md` | Prior session notes. Useful context, but deployment wording is internally stale; use `AI_STATE.md` for the reconciled status. |

1. `data/club-royale-data.js`
2. `data/live-sailing-groups.js`
3. `data/mike-26pas603.js`
4. `data/booked-cruises.js`
5. `data/tully-data.js`
6. `data/member-profiles.js`
